# Synthetic test data for the Mohometer app

Four reproducible CSV files for exercising every code path in the app
without needing real geochemical data. Generated by `gen_test_data.py`
with a fixed seed (42) so the files are stable across runs.

## Files

| File | Rows | Has Crust_Thickness? | What to use it for |
|---|---|---|---|
| `test_training.csv`         | 720 | yes | Model-tab training source |
| `test_validation.csv`       | 240 | yes | Validate-tab held-out dataset |
| `test_prediction.csv`       | 180 | **no** (blanked) | Predict-tab unknown-samples dataset |
| `test_edge_cases.csv`       | 30  | mixed | ICS auto-populate hand-crafted edge cases |
| `test_real_world_messy.csv` | 150 | yes | **Real-world** column-name variants + units + missing-value tokens + ppb conversion |

## Chemistry synthesis (so the proxy + ML models actually work)

Each row's chemistry is derived from a latent **true** crustal-thickness
value (drawn from the region's distribution) by **inverting the published
proxy formulas**:

- **Profeta et al. 2015 (Sr/Y → H_km):** Sr/Y target = 0.90 × H − 7.25
- **Sundell et al. 2021 (La/Yb_N → H_km):** La/Yb_N target = exp((H − 6.9) / 17)

Then 20 % multiplicative noise is added so the proxies don't fit *exactly*
to the thickness. Major-oxide chemistry (SiO₂, MgO, etc.) is sampled
within rock-class envelopes (mafic / intermediate / felsic) drawn from the
region's rock-mix distribution.

Verified correlations on the 720-row training set:

| Quantity | Pearson r vs Crust_Thickness |
|---|---|
| Sr/Y       | **0.894** |
| La/Yb_N    | **0.881** |
| H_Profeta  | 0.894 (RMSE 7.5 km, bias −0.1 km) |
| H_Sundell  | 0.969 (RMSE 3.8 km, bias −0.4 km) |
| SiO₂       | +0.525 |
| K₂O        | +0.483 |
| CaO        | −0.538 |
| FeO        | −0.499 |
| MgO        | −0.464 |
| TiO₂       | −0.428 |

So ML models should reach ~5 km RMSE (better than proxies because they
can use major oxides too) with meaningful per-sample residuals — no
synthetic "perfect prediction" trap.

## What each file lets you exercise

### `test_training.csv`

- **Prepare tab**: column auto-mapping (~25 columns, all canonical names), data-quality panel, anhydrous toggle (oxides sum sensibly), age histogram (spans 0–2900 Ma → log scale auto-triggers), reverse-fill cases none (every row has both Age_Ma and inferred categories).
- **Model tab**: train ExtraTrees + RandomForest + XGBoost side-by-side on the same 720 rows. Each gets its own per-model column. CV will yield meaningful out-of-fold residuals (used for conformal calibration). Feature importance should rank Sr, Y, La, Yb high and the major oxides as supporting features.
- **Group tab**: group by `Dataset` (6 groups, ~120 each), `Tectonic_Setting` (3 groups), or `Geologic_Era` (auto-filled by ICS). Apply groups, see medians per region. Age-distribution histogram with the dataset spread is interesting.

### `test_validation.csv`

- **Validate tab**: 240 held-out samples with known thickness. Six regions × 40 each → multiple groups for the per-group averages table. MSWD will likely sit between 1–3 for tight regions (within-group scatter dominated by model noise) and higher for the Tibet/Andes ones (more geological variability).
- **CI calibration check** should show:
  - Tree CI under-covering (expected ~70–85 %) on bagging ensembles
  - Conformal at ~88–92 % (the statistical guarantee)
- **5 km binned performance table** should show degraded RMSE in the thickest bins (≥60 km, less training data there).
- **Validation plot**: pick Y = `Predicted_<your_primary_model>_km`, X = `Observed_km`. Toggle Conformal CI bars. Filter by group to see per-region calibration.

### `test_prediction.csv`

- **Predict tab**: 180 unknown samples. Crust_Thickness is dropped so the model produces Predicted_km + Conformal CI. Useful for sanity-checking the predictions cluster around the right thickness per region even though the file has no labels.
- **Summary tab**: violin plot will show 6 region clusters; MC-perturbed CI button should reduce to roughly the per-sample CI width over √(N) per group.

### `test_real_world_messy.csv` — 150 rows, real-world column-name mess

Same six regions as the main bench but with **realistic, messy column
headers** you actually see in published / shared geochemical
datasets. Designed to exercise the Prepare-tab auto-mapping registry
+ unit handling + missing-value parsing in one upload.

**Column-name variants:**

| Canonical    | This file uses      | Why it's there |
|---|---|---|
| `Sample_ID`         | `Sample`           | Common short form |
| `Dataset`           | `Reference`        | Publication-style |
| `Lat`               | `Latitude (DD)`    | Full word + unit tag in parens |
| `Lon`               | `Longitude (DD)`   | ditto |
| `Age_Ma`            | `Age (Ma)`         | Unit in parens |
| `Tectonic_Setting`  | `Tectonic Setting` | Space-separated |
| `Arc`               | `Arc Name`         | Synonym |
| `Segment`           | `Volcanic Segment` | Synonym |
| `Geologic_Domain`   | `Domain`           | Abbreviated |
| `Rock_Type`         | `Lithology`        | Domain term |
| `SiO2`              | `SiO2 (wt%)`       | Unit tag |
| `TiO2`              | `TiO2 wt%`         | Unit tag, no parens |
| `Al2O3`             | `Al2O3 (wt%)`      | Unit tag |
| `FeO`               | `FeOt`             | **Iron expressed as FeO-total** (must convert via existing iron→FeO logic) |
| `MgO`               | `MgO (wt%)`        | Unit tag |
| `CaO`               | `CaO_wt`           | Underscore variant |
| `Na2O`              | `Na2O wt%`         | Bare unit |
| `K2O`               | `K2O (%)`          | Generic % unit |
| `Sr`                | `Sr [ppm]` / `Sr_ppb`* | **Two columns** — half the rows in ppm, half in ppb (1000× larger). Tests the unit-aware ingestion path. |
| `Y`                 | `Y_ppm`            | Suffix unit |
| `La`                | `La (ppm)`         | Paren unit |
| `Yb`                | `Yb_ppm`           | Suffix unit |
| `Ce`                | `Ce ppm`           | Bare unit |
| `Crust_Thickness`   | `Moho depth (km)`  | Synonym + unit |

**Plus:**

- **Empty `Period` / `Stage` columns** — present but all-NaN, so the
  ICS auto-populate has nothing to coalesce *into* and must invent the
  hierarchy from `Age (Ma)` alone.
- **3 junk columns** the registry should ignore: `Lab ID`, `Date analysed`, `Comments`.
- **~4 % of cells in chemistry columns** carry real-world missing-value tokens:
  `NA`, `n/a`, `-`, `bdl` (below detection limit), `<0.1` (censored).
  These should land as NaN after the Prepare-tab numeric coercion.

**What to watch for when you upload this file:**

1. The auto-mapping editor should show most columns as **🔵 Blue
   (confirmed)** because the registry has decent fuzzy-matching. Things
   like `SiO2 (wt%)` and `MgO (wt%)` should auto-map cleanly. The
   `Latitude (DD)` / `Longitude (DD)` headers test the location-unit
   detection.
2. **`Sr_ppb` should auto-detect as Sr with unit = ppb**, and the
   processed values should be 1000× smaller than the raw column values
   (because ppb → ppm conversion divides by 1000). If you see Sr
   values in the thousands of ppm range, the unit handling failed.
3. **`FeOt` → `FeO`**: the iron-to-FeO conversion path (see
   `iron_to_feo()` in the source) should pick FeOt up as a valid iron
   source.
4. **`Moho depth (km)`** should map to `Crust_Thickness`. Check the
   Prepare data-quality panel shows it as the target.
5. **Missing-value tokens**: the data-quality panel should report ~4 %
   missing per chemistry column. Make sure the histogram still renders.
6. The **age histogram** has no Period/Stage columns to colour by — pick
   `Geologic_Era` from the colour-by selector once auto-populate has filled
   that column.

### `test_edge_cases.csv` — 30 hand-crafted rows

Each row exercises one specific quirk. Note: a `Note` column documents
what each is for; the app will silently ignore that column. Rows
include:

| Edge | What it tests |
|---|---|
| `EDGE_01–03` | **Forward fill only** — Age_Ma alone, no categories. Should auto-fill Eon / Era / Period / Epoch / Stage. |
| `EDGE_04–05` | **K-Pg boundary** — Age_Ma = 66.0 → Maastrichtian (older); Age_Ma = 65.5 → Danian. |
| `EDGE_06–08` | **Reverse fill** — Stage / Era / Eon alone. Should derive Age_Ma + Min/Max/Error. |
| `EDGE_09`    | **Stage alias column** — uses `Geologic_Stage` (not `Geologic_Age_Label`) — should coalesce. |
| `EDGE_10–11` | **Conflict detection** — Age_Ma + wrong Period/Era. Age_Conflict column should fire; user value NOT overwritten. |
| `EDGE_12`    | **Typo** — `Ordivician` instead of Ordovician — should not match, no error. |
| `EDGE_13–14` | **User value preserved** — pre-filled correct category + Age_Ma → category stays as user typed. |
| `EDGE_15`    | **Case-insensitive** — `cretaceous` (lowercase) — should resolve to Cretaceous. |
| `EDGE_16–18` | **Full samples** — Andes / Aleutians / Tibet exemplars for chemistry + categories. |
| `EDGE_19–21` | **Missing features** — Sr without Y, Yb missing, traces-only. Tests Validate readiness diagnostic. |
| `EDGE_22–23` | **Cambrian unnamed Stage 10** + Terreneuvian Epoch — real ICS names with quirky strings. |
| `EDGE_24`    | **Pridoli** — Silurian Epoch with no Stage subdivision. |
| `EDGE_25`    | **Hadean** — Eon only, others should stay empty. |
| `EDGE_26–28` | **Invalid inputs** — negative age, 10000 Ma, totally empty row. Should fall through without errors. |
| `EDGE_29–30` | **Grouping fodder** — distinct Tectonic + Arc + Era combos. |

## Suggested test sequence

1. **Prepare → upload `test_edge_cases.csv`** → confirm:
   - Geological age auto-population panel reports 17 forward, 5 reverse, 2 conflicts.
   - Conflict table lists EDGE_10 (470 Ma vs Devonian) and EDGE_11 (30 Ma vs Mesozoic).
   - EDGE_06 / EDGE_07 / EDGE_08 reverse-derived rows get Age_Min_Ma / Age_Max_Ma / Age_Error_Ma values.
   - Age histogram renders.
2. **Prepare → upload `test_training.csv`** → assign to Model tab.
3. **Prepare → upload `test_validation.csv`** → assign to Validate tab.
4. **Prepare → upload `test_prediction.csv`** → assign to Predict tab.
5. **Group tab** → group by Dataset → 6 groups appear → Apply → save aggregated dataset.
6. **Model tab** → train ExtraTrees + RandomForest + XGBoost on the training pool entry → confirm 3 entries in `models` dict, primary-model selector active.
7. **Validate tab** → Run validation → confirm:
   - 5 km binned table populated.
   - Per-group averages table has MSWD + Excess σ columns.
   - CI calibration check shows Tree CI under-covering and Conformal near 90 %.
   - Validation plot CI bars dropdown works for both Tree and Conformal.
8. **Predict tab** → Run predictions → confirm Conformal columns on output.
9. **Summary tab** → confirm violin + group prediction summary; click MC-perturbed CI button.

## Regenerating

```bash
cd <project-root>
python test_data/gen_test_data.py
```

Output is deterministic — re-running produces byte-identical CSVs.
Bump `SEED` at the top of the script to get different draws.
